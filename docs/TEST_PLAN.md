# Тест-план игры Jump Game

## 1. Общая информация

**Название проекта:** Jump Game

**Тип приложения:** браузерная 2D-игра

**Жанр:** платформер 

**Платформа:** Web

**Цель тестирования:** проверить корректность работы игровой механики, управления, отображения элементов интерфейса, столкновений, системы очков, игровых препятствий и дополнительных игровых механик.

- проверить движение камеры;
- проверить систему подсчёта очков;
- проверить сохранение лучшего результата;
- проверить появление монстров;
- проверить столкновение персонажа с монстрами;
- проверить появление парашюта;
- проверить работу механики парашюта;

# 6. Основные игровые механики

## 6.1. Персонаж

Персонаж автоматически прыгает вверх и падает вниз под воздействием гравитации.

Игрок управляет горизонтальным движением персонажа.

Доступно движение:

- влево;
- вправо.

---

## 6.2. Платформы

Платформы используются для приземления персонажа.

Платформы генерируются по мере продвижения игрока вверх.

Персонаж должен иметь возможность:

- приземляться на платформу;
- снова прыгать с платформы;
- повторно приземляться на ту же платформу.

---

## 6.3. Монстры

Монстры являются препятствиями.

Монстры появляются через определённое количество обычных платформ.

При столкновении персонажа с монстром игра должна завершаться.

После использования парашюта монстры в безопасной зоне не должны наносить урон персонажу.

---

## 6.4. Парашют

Парашют является дополнительной игровой механикой.

После определённого количества приземлений появляется парашют.

При столкновении персонажа с парашютом запускается специальный режим полёта.

После приземления на специальную платформу создаётся безопасная зона.

В безопасной зоне монстры не должны создавать угрозу персонажу.

---

## 6.5. Система очков

Во время игры отображается текущий SCORE.

Лучший результат отображается как BEST.

Лучший результат должен сохраняться после завершения игры.

---

## 6.6. Game Over

Игра должна завершаться при наступлении условий проигрыша.

После Game Over отображаются:

- надпись GAME OVER;
- текущий SCORE;
- BEST;
- кнопка «ИГРАТЬ СНОВА».

# 9. Приоритеты тестирования

Используется следующая система приоритетов.

### Critical

Функциональность полностью блокирует игру.

Пример:

- игра не запускается;
- пустой экран;
- JavaScript вызывает критическую ошибку;
- невозможно начать игру.

### High

Важная функция работает неправильно и существенно влияет на игровой процесс.

Пример:

- персонаж не может приземлиться;
- столкновение с монстром не работает;
- Game Over не срабатывает;
- управление не работает.

### Medium

Функция работает неправильно, но игра остаётся доступной.

Пример:

- неправильный подсчёт SCORE;
- BEST отображается неправильно;
- парашют появляется с задержкой.

### Low

Незначительная визуальная или косметическая проблема.

Пример:

- небольшое смещение изображения;
- незначительная проблема с размером элемента;
- визуальный дефект, не влияющий на игровой процесс.
